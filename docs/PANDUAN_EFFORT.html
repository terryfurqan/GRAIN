🎚️ Panduan Memilih Effort

Kapan pakai low / sedang / tinggi / extra-tinggi — konteks kerja PAB & PIV Lab

Satu aturan induk: Effort mengikuti taruhan kesalahan, bukan panjang jawaban atau besar-kecilnya tugas.
Kalau salah murah dikoreksi → effort rendah. Kalau salah mahal / lama di-debug → effort tinggi.

Tabel keputusan cepat

EffortPakai untukContoh di kerja Anda
low Ngobrol, tanya-jawab, hal mekanis 1 langkah yang tak butuh mikir konteks
  • Diskusi strategi (seperti sekarang)
  • Geser 3 tombol save ke bawah
  • Ganti teks tombol / warna
  • Tanya "istilahnya apa?"
sedang Edit yang butuh paham sedikit konteks tapi logikanya lurus
  • Tambah tombol spinner ukuran titik POI
  • Auto-maximize window saat buka
  • Ubah ketebalan garis PSG + input pengaturnya
tinggi Fitur nyambung ke wiring lama, ada edge case, "jangan boyak"
  • Sync tabel ke baris tengah (edge: awal/akhir daftar)
  • Split tombol jadi "Slip-all" & "Slip-F#"
  • Fill area sesar + label melayang + checkbox on/off
  • Auto-deteksi start/end (selisih terkecil + toleransi)
extra-tinggi Logika bercabang non-sepele yang gampang salah & mahal di-debug
  • Logika Sub-Fault (luas SF1=HW1→HW2, SF2=HW2→FW, dst.)
  • Seleksi AXPOT: klik kurva vs klik frame + on/off saling pengaruh
max Nyaris tak pernah perlu. Hanya masalah yang benar-benar bikin buntu. Overkill untuk kerja poles GUI. Lewati saja.

Jawaban tegas: obrolan seperti ini?

Cukup low. Diskusi itu murah dikoreksi — salah tinggal tanya balik, tak ada kerusakan. Boros effort di obrolan = mubazir. Anda sudah benar mematikannya jadi low tadi. 👍

Tes 3 detik sebelum memanggil saya

❓ "Kalau hasilnya salah, ruginya apa?"

Cuma perlu tanya ulang → low. Baru ketahuan setelah GUI error & debug lama → high/xhigh.

❓ "Ini nyambung ke kode lama?"

Berdiri sendiri / mekanis → low–sedang. Harus paham struktur file utuh dulu → high.

❓ "Ada logika bercabang / edge case?"

Tidak → sedang. Ya, & salah = mahal → xhigh.

❓ "Ini soal rasa (ukuran/posisi)?"

Effort tak menolong — mata Anda yang menentukan. Pakai sedang, lalu iterasi lihat GUI.

Jebakan yang harus dihindari

  • "Tugasnya kecil, ya low." — Keliru. Sub-Fault itu "kecil" tampilannya tapi logikanya berat → butuh xhigh.
  • "Biar aman, semua max." — Boros & lambat tanpa hasil lebih baik untuk tugas ringan.
  • Model ≠ effort. Tetap pakai Opus (model terkuat) di semua level; yang Anda putar hanya effort-nya.
  • Fast mode boleh nyala kapan saja — mempercepat output, tidak menurunkan kualitas.
