Dokumen ini memetakan seluruh modul PAB: 7 langkah pipa utama (Step 0→4) plus 4 alat standalone yang menyisip di antara langkah. Setiap modul = 1 file .m di akar PAB/, dijalankan setelah pab_setup. Satu kebenaran (one truth) per tahap; alat lanjut tiap modul menjaga pekerjaan tak ditinggal sebelum tuntas.

1. Peta pipa

Garis biru = pipa utama (urutan Step). Kotak ungu = alat standalone non-destruktif yang menyisip. Panah putus-putus = membuka modul berikutnya lewat tombol "Lanjut".

3. Pipa utama (Step 0 → 4)

PAB0 Step 0 · QPIV
Saring foto bermasalah sebelum langkah berat, lewat Quick PIV pada strip tipis.
  • Deteksi frame mati (mesin berhenti: |V| puncak ≈ 0).
  • Deteksi interval tak teratur (shutter counter roll-over: dt EXIF outlier).
  • Multi-folder; layout 3 kolom (daftar exp · axMain/PSG/POT · tabel frame).
  • Exclusion non-destruktif → Save/Load Progress per-root.
in folder JPG out daftar exclusion → tombol "Lanjut → Step 1"
Tampilan GUI PAB0 — 3 kolom (daftar exp · axMain/PSG/POT · tabel frame).
PAB1 Step 1 · ROI jitter
Tentukan ROI anchor stabilisasi (uji jitter area kecil) untuk banyak eksperimen sekaligus.
  • Scan rekursif ROOT → daftar eksperimen.
  • ROI tarik-sekali (▭/⬡) + 4-kurva auto-jitter; pinjam/sebar ROI antar-exp.
  • Filter frame yang lolos QPIV Step 0.
  • Handoff: tombol "Lanjutkan ke Step 2" memproduksi semua MAT PREP → buka PAB2.
in JPG + exclusion out MAT PREP
Tampilan GUI PAB1 — ROI jitter multi-eksperimen + handoff ke Step 2.

4. Sisipan: PABMASK standalone non-destruktif

PABMASK
Masking kotak putih borderless yang ukurannya diinterpolasi per-frame antara kondisi awal & akhir — menutup area belakang dinding pendorong / bukan-pasir yang mengotori vektor PIV.
  • Beroperasi pada MAT PREP (di antara Step 1 dan Step 2).
  • Hanya menyimpan resep (koordinat kotak awal+akhir) di prep.masking — blob JPG asli utuh.
  • Kotak ditempel saat decode (unpackMat/readMatFrame); GS regen dari RAW ter-masking ikut bersih.
  • Tombol "Tampilkan frame ini" (preview on-demand) + Save/Load Progress per-folder.
in/out MAT PREP (in-place, reversible)
Tampilan GUI PABMASK — editor kotak putih interpolasi awal→akhir.
PAB2 Step 2 · PIV penuh
Analisis PIV penuh dengan input .mat (bukan folder) — padanan persis PIVlab_automasi_batch_GUI_V4.
  • PIV + GS tersemat + waktu EXIF (px/s) + geometri strain bertanda + Quick PIV buang frame mati.
  • Override IW pass 1–4; config QPIV Step 0 terbawa lewat jembatan key RAW↔.mat.
  • Keluaran 1 file per exp ke PIV_<tgl>/ di root.
  • Produksi paralel antar-folder (1 worker = 1 folder).
in MAT PREP out MAT PIV
Tampilan GUI PAB2 — analisis PIV penuh, input .mat per-eksperimen.

5. Sisipan: MATPIVEDIT standalone

MATPIVEDIT
Koreksi geometri X0 / X1 / L_pos (cm) pada MAT PIV yang sudah ada — tanpa menjalankan ulang PIV.
  • Peneliti melihat foto awal & akhir (latar GS ber-penggaris-cm) untuk memutuskan nilai benar.
  • Saat Simpan, strain dihitung-ulang otomatis (pivanalyze.geom.computeGeometry) + backup .bak.
  • 2 kolom: tabel banyak MAT PIV · kanvas foto awal/akhir.
in/out MAT PIV (in-place + .bak)
Tampilan GUI MATPIVEDIT — edit X0/X1/L_pos + kanvas foto awal/akhir GS.

6. Step 3 — Pratinjau & Assign

PAB3 Step 3 read-only
Pratinjau cepat output Step 2.
  • axMain (skalar velmag/shear + GS + slider frame) — di sini garis PSG ditarik.
  • axPOT (kurva |V| sepanjang garis, auto-PSG 70%).
  • Montase → PNG (grid / 2-kolom). Tak menyentuh berkas.
Tampilan GUI PAB3 — axMain (skalar+GS) di atas, axPOT di bawah.
PAB3a Step 3a
Assign kurva POT → label HW-#/F/F0/FFW di atas MAT PIV.
  • POT disampel sendiri dari garis PSG (tanpa Step 1 PIVTerry).
  • Auto-save <base>_autopot.mat (format kompatibel suite PIVTerry).
  • Round-trip restore; jadi seed baca-saja untuk PAB4.
Tampilan GUI PAB3a — assign kurva POT → label HW + tabel kurva.

7. PAB4 — Step 4 terpadu 5 tab

PAB4
Satu app, ruang kerja sama (1 dataset, 1 garis PSG, 1 truth _potdata.json + _comments.json). Tak ada reload antar-operasi. PAB4A/PAB4B kini forwarder tipis ke tab tertentu.
  • Garis PSG: exp baru mulai 75% tak-terkunci; setel lalu kunci untuk sampel. Exp dengan garis di _potdata langsung aktif (terkunci+seed); fallback ke seed _autopot PAB3a (baca-saja).
  • Net-slip negatif auto-clip ke 0; HW jadi titik ikat cerita sesar.
  • Ekspor Claude: bundel PAB4_claude/<base>/ = comments.json + curves.json (data numerik kurva HW) + hw_story.json + PNG per-komentar + README pengarah.
  • Sumbu-X gambar produksi Frame ↔ Strain% (live tetap Frame).
Tampilan GUI PAB4 terpadu — ruang kerja axMain+axPOT (kiri) & panel kanan 5 tab.

8. Alat ekspor figur standalone

PABEXPORT
WYSIWYG katalog gambar AX main (velmag + shear) untuk arsip persisten.
  • Kanvas 1-frame + slider + toggle velmag↔shear; preview = byte-identik dengan export.
  • Tombol EXPORT → render semua bingkai → PAB_export/<exp>/velmag|shear/ + manifest histori.
  • Immutable (hapus+regenerate, tanda ⚠BASI bila fingerprint berubah). Setelan GLOBAL ke file (setpref) + SESSION; DPI/CLim auto.
in MAT PIV out PAB_export/
Tampilan GUI PABEXPORT — kanvas WYSIWYG + setelan render katalog.
PABAXPOT
Editor figur AX POT grade-paper — merakit kurva untuk bercerita, tanpa sistem komentar.
  • Baca <base>_axpot.mat (ekspor PAB4 tab ⑤ "Save as AX POT").
  • Kanvas WYSIWYG fisik (cm); renderer dipakai bersama preview & export → paritas terjamin.
  • Keluaran PNG/JPEG + JSON sidecar; titik informasi disimpan balik ke .mat.
in _axpot.mat out PNG/JPEG + JSON

9. Sistem Komentar & Deskripsi PAB4 ↔ Claude Cowork

Tab ③ PAB4 bukan sekadar catatan. Ini kanal dua-arah antara peneliti dan Claude: peneliti menulis deskripsi/interpretasi yang tertaut ke objek eksperimen (frame, garis PSG, kurva HW, titik), PAB4 memproduksi gambar yang sinkron persis dengan tiap komentar, lalu mengekspor semuanya sebagai bundel yang dibaca Claude Cowork (CLCW) untuk menyusun laporan ilmiah. Tujuannya: Claude membaca narasi + gambar + angka tanpa ambiguitas.

9.1 Dua peran Claude

PeranSingkatanTugas
Claude Code (di MATLAB/repo)CLCCMembangun & memelihara modul PAB; menjalankan ekspor; menjamin bundel konsisten (guard fingerprint, tulis _HANDSHAKE.md).
Claude Cowork (pembaca bundel)CLCWMembaca PAB4_claude/, menafsirkan komentar+gambar+angka, menulis REPORT.md, opsional membalas komentar sebagai role:"CLAUDE".

9.2 Alur kanal

9.3 Anatomi satu komentar

Tiap komentar = satu objek di <base>_comments.json (kebenaran per-eksperimen, di samping .mat). Yang membuatnya kuat: tertaut dan self-describing.

FieldArti
id · time · roleIdentitas (c001…), waktu, USER atau CLAUDE.
frame · psgId · curveKonteks tempat komentar dibuat: nomor frame, garis PSG (id stabil), kurva/label HW aktif.
textDeskripsi/interpretasi peneliti (markdown bold; bisa panjang multi-baris). Boleh sisipkan tag inline.
refsRujukan terstruktur auto-tangkap: exp/psg/curve/frame/strainPct/posPx — angka konkret, bukan sekadar teks.
images3 gambar Export-3 (velmag/shear/axpot) tab ③, bila ada.
assets[]Gambar ber-spec tab ④ (lihat 9.4): kind/file/spec/fingerprint/producedAt.

Tag inline = rujukan objek di tengah kalimat (konsistensi penyebutan unsur): @exp:<base> (wajib, auto-prepend), @psg:<id>, @curve:HW-N, @frame:N, @strain, plus rujukan POI. Jadi saat CLCW membaca "...melintasi @curve:HW-2...", ia tahu persis kurva mana dan bisa menariknya ke angka di curves.json.

9.4 Gambar sinkron-tag (tab ④ Produksi Gambar)

Masalah klasik: narasi bilang X, gambar menunjukkan Y. PAB4 menutupnya dengan kontrak sinkron: satu shotSpec menggerakkan render PNG dan ditulis ke JSON — UI tak pernah dibaca ulang saat ekspor, jadi PNG ↔ JSON tak bisa beda.

  • spec mencatat apa yang ditampilkan: panel (velmag/shear/axpot), frame, garis PSG, kurva HW yang tampak, titik, CLim, xUnit (frame/strain%).
  • fingerprint (FNV-1a 8-hex, urutan-kurva-invarian) = "sidik jari" data-penentu. Bila peneliti re-label / trim / geser garis / ubah CLim, fingerprint berubah → gambar lama ditandai ⚠BASI.
  • caption tertanam di PNG (exp · frame n/N · strain% · psg · isi) → gambar tetap bercerita meski lepas dari JSON.
  • CLim terkunci per-eksperimen (manifest.json) → semua PNG eksperimen berskala sama (komparabilitas paper).

9.6 Protokol jabat-tangan (CLCC → CLCW)

Setiap Export, CLCC menjalankan guard otomatis: tiap asset terdaftar harus punya file; tiap PNG harus terdaftar (anti-yatim); fingerprint asset harus padan fingerprint dari spec-nya. Hasil ditulis ke _HANDSHAKE.md:

✅ SINKRON — registry↔file konsisten, fingerprint padan → CLCW boleh melapor.
⚠️ DESYNC — ada over-claim / yatim / fingerprint beda → CLCW jangan melapor; minta CLCC re-export.

Konvensi pelaporan CLCW: saat menulis REPORT.md, sebutkan jumlah asset per komentar + fingerprint yang dibaca, agar CLCC bisa konfirmasi versi data yang dipakai memang terkini. Balasan CLCW (opsional) ditulis sebagai komentar baru role:"CLAUDE" (frame/psgId/curve sama) → muncul inline di tabel PAB4 dengan prefiks [CLAUDE]:, bukan kolom terpisah.

Engine: pivcore.io.pab4Comments (CRUD atomic + exportClaude/verifyBundle/writeHandshake/writeClaudeReadme), pivcore.io.pab4Shots (specStruct/fingerprint), pivcore.io.pab4Curves (curves.json). Semua murni/headless & lulus R2025b.

10. Sampling Eulerian AX POT

Inti analisis POT: kita tidak mengikuti partikel pasir (itu Lagrangian). Kita pasang deret probe diam di sepanjang garis PSG — posisinya tetap di ruang sepanjang eksperimen. Tiap frame, tiap probe membaca |V| pada selnya (rata-rata blok 3×3). Material bergerak melewati probe; probe merekam apa yang lewat. Itulah sampling Eulerian.

Analogi untuk pimpinan: bayangkan deretan sensor kecepatan dipaku di dasar sungai. Sensor tak ikut hanyut — air mengalir melewatinya. Tiap sensor mencatat "seberapa cepat air lewat sini, tiap detik". Garis PSG = barisan sensor; sumbu waktu = frame (atau strain kumulatif %); puncak kurva = saat sesar/hanging wall melintasi sensor itu.
AspekEulerian (yang dipakai PAB)Lagrangian (bukan ini)
Yang diamatiTitik tetap di ruang (garis PSG)Partikel material yang ikut bergerak
Pembacaan|V| yang lewat tiap probe, per frameLintasan tiap partikel sepanjang waktu
Sumbu kurvaposisi probe & waktu/strainperpindahan partikel
Untuk apaMendeteksi kapan & di mana sesar/HW melintas (puncak kurva)Melacak deformasi partikel individual

Implementasi: pivcore.pot.step1Collect.collectAlongLine menebar n = floor(L/spacing)+1 probe pada garis p1→p2; tiap probe mengambil rata-rata blok 3×3 sel PIV per frame → deret-waktu (1×nFrames). Inilah record yang di-label HW di PAB4 dan dirender sebagai AX POT.

11. Contoh output gambar

Empat jenis keluaran kanonik yang dihasilkan pipa, dari data contoh nyata (TKS / P-CON). Vel mag & shear strain = gambar AX main (PABEXPORT / PAB4 tab ④). AX PSG = medan skalar dengan garis PSG tempat sampling. AX POT = profil |V| sepanjang garis itu, dianalisis lintas frame.

Vel mag (velocity magnitude)P-CON-4cm-F-1: medan |V| + overlay GS + glyph (keluaran PABEXPORT); CLim terkunci per-eksperimen.
Shear strain (strain rate)P-CON-4cm-F-1: bidang shear du/dy+dv/dx bertanda; skala simetris.
AX PSGGaris PSG (merah) di atas medan |V| (P-CON-4cm-F-1) — lokasi pengambilan profil.
AX POT (Plot Over Time)P-CON-4cm-F-1: |V| (cm/s) tiap titik sepanjang garis PSG vs strain kumulatif (%); envelope hitam = max indenter, lembah = jejak sesar/HW.

12. Cara menjalankan

Sekali per sesi MATLAB (selalu R2025b):

pab_setup

Lalu, mengikuti urutan pipa:

PAB0 → PAB1 → PAB2 → PAB3 / PAB3a → PAB4

Alat standalone dipanggil kapan perlu: PABMASK, MATPIVEDIT, PABEXPORT, PABAXPOT. Tiap modul menerima argumen folder root opsional (mis. PAB2(prepDir,true)) dan punya tombol "Lanjut" ke modul berikutnya agar pekerjaan tak ditinggal sebelum tuntas.

Catatan governance. Akar PAB/ hanya berisi PAB* + pab_setup + paket. _reference/ (PIVprep_V2 + PIVTerry) = inspirasi baca-saja — jangan dikembangkan / dipanggil lintas-folder.

13. Rencana web katalog hasil

Tahap lanjut (di luar pipa MATLAB): membuat katalog web read-only agar seluruh anggota lab dapat melihat hasil akhir analisis PIV dari mana saja lewat URL. Saat ini hasil hanya berupa berkas lokal di mesin operator (PAB/PAB_export/ + EXP_coll/) dan tak bisa diakses bersama. Rencana ini tidak menyentuh modul PAB mana pun — ia hanya menurunkan katalog dari keluaran yang sudah ada.

13.1 Prinsip yang dikunci

AspekKeputusan
AksesInternet publik; semua anggota lab membuka via URL.
SifatRead-only — hanya melihat. Tersedia browse + filter/cari + download.
Konten100% JPEG. Data mentah .mat (~1,1 GB/exp) tak pernah ke web; tetap di sistem operator. Yang disajikan: velmag, shear, GS, axPOT, PSG — semuanya gambar.
PembaruanManual oleh operator: ekspor MATLAB → sync ke web.
Numerik axPOTFase berikutnya, bukan v1. Datanya sudah ada di _potdata.json; arsitektur menyiapkan tempatnya saja.
BiayaSekitar $5–10/bln; diajukan ke ITB.

13.2 Pilihan teknologi

Karena hasil sudah statis (gambar + JSON) dan tak perlu komputasi server, web-nya adalah situs statis: HTML + CSS + JavaScript — bukan server Python. Python hanya dipakai sebagai script bantu upload yang dijalankan sekali per batch, bukan sebagai backend.

13.3 Arsitektur

Cloudflare R2 dipilih karena egress (bandwidth) gratis — keunggulan utama dibanding S3/B2 untuk penyajian gambar. Pages menghosting situs statis gratis. Opsi Google Drive dan komputer-lab-nyala-terus ditolak (rate-limit/URL rewel; uptime/IP rapuh).

13.4 Komponen yang dibuat (semua baru, terpisah dari MATLAB)

A · Script sinkronisasi web/sync/
Python 3, satu berkas, pakai boto3 (R2 kompatibel-S3). Dijalankan manual tiap selesai ekspor.
  • Scan PAB_export/ + pasangan EXP_coll/<grup>/<exp>_axpot.jpg & _potdata.json.
  • Hitung ulang jumlah frame per scalar dari isi folder (abaikan count JSON yang bisa basi).
  • Parse nama exp → kolom filter (type/thickness/slope/sequence/pivMode/resolution).
  • Upload JPEG ke R2 (datasets/<exp>/<scalar>/fNNN.jpg); idempoten — skip yang sudah ada.
  • Generate site-catalog.json ramping (bukan manifest penuh) untuk situs.
B · Situs statis web/site/
HTML + CSS + JavaScript vanilla, tema terang (dark dilarang).
  • index.html — tabel daftar eksperimen + filter (slope/type/thickness) + pencarian + thumbnail.
  • experiment.html?exp=<id> — detail: panel peta/penampang/analisis, slider frame velmag+shear (navigasi ←/→), panel axPOT, tombol download, sidebar metadata.
  • Slot kosong "Kurva numerik (segera)" untuk fase axPOT numerik.
  • style.css (light grid responsif), app.js (list+filter), viewer.js (slider + preload tetangga).
C · Deploy
  • Buat bucket R2 (mis. piv-lab), aktifkan akses publik / custom domain.
  • Hubungkan Pages ke web/site/ (atau unggah langsung).
  • web/README.md: set .env, jalankan publish.py, publish Pages, catatan biaya & ajuan ITB.
D · Fase berikutnya — axPOT numerik bukan v1
Tempatnya disiapkan sekarang, implementasi nanti.
  • publish.py ikut upload _potdata.json ke datasets/<exp>/axpot/potdata.json.
  • experiment.html isi slot "Kurva numerik" dengan plot interaktif (uPlot/Chart.js) + unduh CSV.

Data acuan (read-only, jangan diubah): PAB_export/_catalog.json (indeks global), PAB_export/<exp>/manifest.json (spec + daftar file scalar), folder velmag/ & shear/ (JPEG ~238 KB), EXP_coll/<grup>/<exp>_axpot.jpg, dan _potdata.json (kurva sebagai angka, untuk fase numerik). Penamaan exp terurai jadi kolom filter mengikuti kode kanonik penamaan eksperimen. Penting: jumlah frame dihitung dari isi folder, bukan dari count di JSON (bisa mismatch saat render belum tuntas).
